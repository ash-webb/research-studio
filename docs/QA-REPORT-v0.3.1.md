# Browser QA report — v0.3 → v0.3.1

**Date:** November 1, 2026
**Browser:** Chromium (Playwright), desktop 1360×900 and phone 390×844
**How to rerun:** `npm run test:e2e` (writes screenshots and `e2e-report.json` to `tests/e2e/output/`)

All sessions in this report were generated by a test script. They are software checks, not research data.

## What was tested

Scripted participants completed every bundled example study through the real participant page (`study.html?study=…`). For each run, the test checked the events stored in the browser, the researcher dashboard (summary cards, Activity outcomes table, Method analysis) and all seven exports (Task, Survey, Clicks, Method, A/B exposures and Method events CSVs, plus Full JSON) against what the script actually did.

## Defects found and fixed

The same test suite was run against the original v0.3 code: these checks fail there and pass in v0.3.1. Everything else passed on v0.3, so all study types worked end to end. The defects were in how some outcomes were recorded and counted.

1. **Researcher preview runs were counted as participant sessions.** A "Preview locally" run was stored exactly like a real session, so it appeared in the dashboard, the session counts and every export.
   *Fix:* preview sessions are labelled (`session_started.payload.preview: true`). The participant header says "Preview · not counted in results". The Results tab hides preview sessions from the dashboard and all exports by default, says how many it hid, and offers **Include my "Preview locally" runs**. Included previews are marked "Preview" in the session list. Sessions recorded before v0.3.1 have no label and are still counted.

2. **First-click success was reported two different ways.** With one hit, one miss and one "I'm not sure where to click", the Activity outcomes table showed **1 of 3** but the Method analysis showed **1/2 (50%)**.
   *Fix:* both views now count "not sure" as a scored attempt without a hit (**1/3**), the same way the tree test treats "I cannot find it". The analysis adds a "Not sure (no click)" count, so the denominator is visible.

3. **"I'm not sure where to click" stayed available after the first click**, even though the screen says the first click is final. Choosing it after clicking produced a contradictory record (a click marked as not chosen).
   *Fix:* the option is withdrawn once a click is made. A `first_click_unsure` method event is recorded when it is used.

4. **Missing evidence was exported as failure.** In the Task CSV, `observed_success` was `false` for every method that produces no success evidence (card sorts, preferences, surveys, unscored first-click tests) and for prototype tasks where the tracker never connected. That contradicts the project rule that missing evidence is not failure.
   *Fix:* `observed_success` is now left out of stored events and exported as a blank cell when there is no evidence. Prototype tasks also record `success_signal_status` (`received` / `not_observed` / `unavailable`), matching A/B tasks. A prototype analysis with no configured signal says "No signal configured" instead of showing a rate.

5. **Minor layout:** the tree-test help line sat directly against the action buttons. Spacing added.

Five unit tests in `tests/qa-fixes.test.js` cover fixes 1, 2 and 4 without a browser. `npm test`: **53 / 53 pass**.

## Observed but not changed

- **An imported or newly built study's results can only be viewed in the tab where it was imported.** Drafts are held in memory, so after a reload the study is missing from the Results list until its JSON is added to `studies/index.json`. This matches the existing "unsaved drafts are not kept" limitation, but it is easy to trip over during piloting.
- **Refreshing the participant page mid-study starts a new session.** This is a known limitation in the handoff notes and was not retested.
- **Studies shown in the Results list come only from `studies/index.json` plus the study currently open in the builder.**
